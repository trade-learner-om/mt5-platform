## 2026-06-18

### Added

- Added Android system notifications for price alert create and trigger events over `/ws/live` (`category: price_alerts`).
- Added backend notification rows when price alerts are created (`PRICE_ALERT_CREATED`) and when live evaluation triggers them (`PRICE_ALERT_TRIGGERED`).

### Changed

- Renamed the web Price Alerts inactive tab label to **History**; triggered alerts already move to `INACTIVE` server-side and now auto-switch the UI to History on new triggers.

### Fixed

- Fixed stale price alerts ringing again when opening the create-alert flow by tracking only new `triggered_at` transitions and persisting played alert ids in `sessionStorage`.

### Changed

- Extended the Android app with Trading tab retryable/automatic trade management flags, Positions order activity timeline, a GOLD strategy tab with stop support, and forex strategy stop buttons.
- Redesigned the Android app with bottom navigation, modal order/alert sheets, a strategies hub, parallel dashboard loading, longer API timeouts, backend health checks, and watchlist-to-trade prefill.

### Fixed

- Fixed Android boot/login showing a blurred auth screen under the loader by using a dedicated full-screen session loader and navigating to home immediately after authentication while data syncs in the background.

### Changed

- Android Alerts tab now matches web detail: live price, pip distance with color-coded pills (rose/amber/sky/emerald bands), created/triggered timestamps, order details, and symbol grouping with collapsible sections. WebSocket subscribes to active alert symbols for live quotes.
- Android bottom navigation uses Material icons (watchlist star, candlestick trade, positions stack, alert bell, strategies grid) with filled/outlined selected states.
- Android Alerts layout: removed duplicate symbol in expanded cards, fixed symbol wrapping and row alignment, compact distance pills, clean triggered-state text, and merged live price updates so collapsed groups keep distance metrics.
- Added native SwiftUI iOS app (`apps/ios-app`) matching the Android client: host setup, auth/biometric unlock, watchlist, trading, positions, alerts, strategies hub, websocket live data, and local notifications.

### Changed

- Pending orders (`PENDING`, `PLACEMENT_PENDING`) are editable on web, Android, and iOS. Edit entry, stop loss, target, and quantity via `POST /orders/{order_id}/modify`. When quantity changes, the broker order is cancelled and re-placed; when quantity stays the same, entry/SL/target updates are sent in place at the broker.

### Fixed

- MT5 `retcode=10015 Invalid price` on order placement/modify/close: entry, stop loss, target, and market prices are now aligned to each symbol's tick size and decimal precision before `order_send`.
- Order quantity across web Positions, alerts, risk preview, strategy pages, and close-position modal now displays with two decimal places (`0.00`) via `formatQty`.
- iOS host checks failed while Android worked: added `NSLocalNetworkUsageDescription`, HTTP ATS allowance for LAN dev servers, and a dedicated LAN ping session without `waitsForConnectivity`.
- iOS home screen icon now uses the same SignalBridge chart/wave artwork as the Android launcher (`AppIcon-1024.png`).
- At that point, the iOS build shipped with a fixed public host and ATS allowances for that deployment so it could skip the host setup screen.

### Fixed

- Forex strategy target inputs on web no longer reset while typing; live websocket updates were re-syncing `TargetEditor` state on every tick.
- Forex strategy risk amount fields in the config panel no longer reset mid-edit when websocket config snapshots arrive.

### Changed

- Forex strategy price exit targets are now account-scoped: each execution account has its own target ladder, validated and exited independently on web, Android, and iOS.
- Web forex targets are added one at a time via POST (matching GOLD strategy) instead of bulk PUT replace while typing.

### Added

- Platform-wide broker symbol mapping via `symbol_resolver.py`: users can enter canonical names like `GOLD` or `XAUUSD` and the backend resolves to broker-native symbols (e.g. Vantage `XAUUSD+`).
- Per-account `symbol_aliases` on international MT5 accounts with auto-detect on connect, `GET /accounts/{id}/symbols/resolve`, and `PATCH /accounts/{id}/symbol-aliases`.
- Manage Accounts UI for editing the GOLD broker symbol alias; GOLD Strategy page shows the resolved broker symbol for the active account.

### Changed

- International price precision now follows each broker symbol's MT5 `digits` field end-to-end: live ticks, risk preview, alerts, strategy targets, and order placement all normalize to the broker tick grid before display or MT5 calls. Web order inputs round on blur to the broker decimal count.
- Android and iOS summary pills are now tappable: P/L opens Positions (Today), Orders opens Positions (History), and Alerts opens the Alerts tab. Mobile Positions screens include Today/History tabs with broker trade history.

### Fixed

- Vantage gold symbol `XAUUSD.TV` no longer returns 500 on symbol resolve: exact broker matches run before GOLD heuristics, MT5 symbol names keep broker casing, and symbol-spec lookup errors return 400 instead of crashing the API.
- MT5 candle and live price polling no longer force uppercase symbol names, so mixed-case broker symbols like Vantage `XAUUSD.tv` resolve correctly before `symbol_select`.
- Live websocket connections now stay active during browser/app inactivity: backend sends heartbeat pings every 20 seconds, clients respond with pong and send their own keepalive pings, and the web app reconnects when a hidden tab becomes visible again.
- Forex strategy and other live views now resolve prices by normalized symbol key, so broker symbols like `XAUUSD.tv` show live prices even when the UI stores mixed casing.
- Forex strategy open positions now restore entry/1R risk context from persisted `forex_risk`, broker fill entry, and setup-candle fallbacks when live order fields are incomplete after broker reconciliation.
- Live prices no longer freeze until a manual refresh: MT5 polling restarts when the poll task dies or a symbol lookup hangs, websocket heartbeats refresh market streams and push snapshots, broker symbol casing is preserved during stream setup, and web/Android/iOS clients force reconnect when price snapshots go stale for 45 seconds.
- Closed positions no longer show Book P/L as 0.00: final realized profit is preserved from the last running P/L on close, resolved from MT5 deal history when available, and backfilled for recent closed orders during broker reconciliation.
- Closed position Book P/L resolution now re-runs for stored 0.00 values, matches MT5 deals by position/order ticket and symbol timing, stores last broker profit while positions are open, and resolves P/L on every live snapshot and active-orders fetch.
- Active partially booked positions now resolve booked P/L from MT5 exit deals; Closed Today has inline status and account filters (default active account, All option), total P/L as a colored pill, and row P/L as a plain amount without the Book label. Order payloads now include `account_id` for client-side account filtering.
- Closed Today now loads closed trades from MT5 broker history for today (same source as History), while cancelled and failed rows still come from platform orders.
- iOS Closed Today account filter uses iOS 16-compatible `onChange` handlers instead of the iOS 17 two-parameter form.
- iOS dashboard visual refresh: explicit heading colors, sky/indigo palette aligned with web, gradient screen headers, improved cards/chips/tab bar, and light color scheme on dashboard so titles stay visible in system dark mode.
- Android and iOS now enforce broker `price_digits` on all displayed prices: digits are parsed from watchlist, live websocket ticks, and add-symbol responses, cached in app state, and applied via `formatPrice` across watchlist, positions, alerts, strategies, and planner screens.

### Changed

- Backend MT5 terminal reads no longer block the asyncio event loop: `get_terminal_state()` is async and runs under the MT5 session lock via `asyncio.to_thread`, and terminal process discovery on REST routes uses background threads.
- Live websocket snapshots no longer run broker reconciliation inline; reconcile is scheduled as single-flight background work per user with an 8-second debounce, and tick processing uses a per-user mutex to avoid overlapping order automation.
- Web, Android, and iOS clients follow Option A live-data architecture: orders, alerts, prices, and strategy state update from `/ws/live` snapshots only; REST is used for commands and bootstrap metadata (`/auth/me`, watchlist, planner plans), not post-command polling of `/orders/active` or `/price-alerts`.
