## 2026-06-26

### Changed

- Made the live websocket snapshot reconcile open broker positions across every added international account (not just accounts that already had tracked orders) by passing `include_all_accounts=True` from `state_manager.push_snapshot` through `market_data_stream.schedule_background_reconcile`, so positions opened on non-selected accounts now appear in the live feed.
- Grouped the "Pending Orders & Positions" active view in `apps/frontend-react/src/App.jsx` by account, rendering one table per account with a per-account running P/L badge so each account's open positions are shown together.
- Added automatic end-of-week expiry for fresh-position pending orders in `metaapi_client.place_pending_order`: Stop/Limit entries now use MT5 `ORDER_TIME_SPECIFIED` with an expiration of the upcoming Friday 23:59:59 IST (rolling to next Friday once that moment passes). The broker offset is inferred from the symbol tick so the IST wall-clock target maps to the correct server time, and symbols that do not support a specified expiration fall back to GTC. Market orders are unaffected because they fill immediately.
- Fixed `TradingChart` crash (`setMarkers is not a function`) after upgrading to `lightweight-charts` v5 by using the v5 `createSeriesMarkers` primitive instead of calling `series.setMarkers` directly on the candlestick series.

### Notes

- The live snapshot reconcile now connects to each international account's local MT5 terminal on its throttled background pass; accounts whose terminals are not running are skipped and logged, matching the existing `/orders/active` behavior.
- Added `apps/backend-python/test_friday_expiry.py`; it requires Python 3.10+ (the repo runtime) and was validated for date/offset correctness locally since this machine only has Python 3.9.
