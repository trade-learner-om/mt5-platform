## 2026-06-20

### Changed

- Migrated the backend database client from direct `pymongo.MongoClient` usage to a Motor-backed runtime in `apps/backend-python/app/db.py`, with a compatibility layer that keeps existing collection-style call sites working while running MongoDB operations through `AsyncIOMotorClient`.
- Added a dedicated local MT5 session manager inside `apps/backend-python/app/services/metaapi_client.py`, replacing the old loop-bound global session lock with per-account thread-safe session serialization keyed by account/server/path.
- Moved backend startup admin seeding, `/health` MongoDB ping, and auth user lookup off the main asyncio event loop with background-thread execution.
- Shifted the websocket live-state hot path toward async-safe execution by offloading snapshot enrichment, alert evaluation, and strategy snapshot reads to worker threads.
- Shifted primary live tick strategy/runtime work off the main event loop: M1 candle persistence, manual order runtime, trade planner runtime, price-alert automation, GOLD strategy, and Forex trigger strategy now execute through worker-thread coroutine offloading from `market_data_stream.py`.
- Moved primary-stream symbol-set discovery and selected-account lookups in `market_data_stream.py` off the main event loop so stream refresh and re-subscribe work do not block live websocket traffic.
- Moved route-facing market-data restore, stream refresh, order reconcile, and pushed-tick ingestion calls in `apps/backend-python/app/main.py` onto the worker-thread coroutine bridge so live MT5 traffic no longer runs directly on the FastAPI event loop.
- Converted major request-path and live-state MongoDB access to native awaited Motor calls across auth, admin, account selection, watchlists, Indian market session routes, price alerts, order routes, trade planner routes, websocket auth, and the live snapshot/Indian stream services.
- Extended native awaited Motor usage into async runtime coroutines for manual order management, trade planner execution, price-alert automation, and the GOLD/forex strategy runtimes, while keeping explicit broker commands and placement locks on their existing controlled paths.
- Switched the frontend default API base to `https://api.signalbridge.in`, and changed the Android and iOS clients to connect directly to `https://api.signalbridge.in` / `wss://api.signalbridge.in/ws/live` instead of deriving backend URLs from a frontend `:5173` host.
- Added `scripts/mt5-backend.bat` as a backend-only Windows launcher with `start`, `stop`, `restart`, and `status` commands, reusing the same backend environment/bootstrap behavior as the full platform launcher.
- Fixed startup/live-stream callback bridging so worker-thread market-data restore and tick-ingest paths marshal websocket snapshot pushes back onto the main server event loop instead of awaiting Motor futures from the wrong loop.
- Fixed the Motor compatibility layer so every awaited `*_async` Mongo helper also marshals onto the dedicated Motor event loop, preventing startup restore and live snapshot paths from mixing futures across asyncio loops.
- Moved live tick queue/task execution onto a dedicated market-data tick loop so cached tick tasks, per-user serialization, and snapshot debouncing no longer bind to whichever callback loop delivered the latest price update.
- Fixed the Android Positions history screen to use `state.priceDigits` for broker trade price formatting, resolving the `Unresolved reference 'priceDigits'` build failure in `MainActivity.kt`.
- Fixed Android and iOS live-state parsing for saved price alerts by accepting the backend snapshot key `price_alerts` with a camelCase fallback, restoring mobile alert visibility.
- Updated Android and iOS auth boot UI to hide raw production host text during connection and show the app icon on both the login screen and loader screen for the fixed-backend mobile builds.
- Removed the Android fixed-backend app's fallback into the generic host-entry boot screen; production backend failures now stay on a retry-only direct-backend screen so users are never asked for a primary host.
- Removed the Android app's legacy primary-host component and configurable-host boot path entirely; the app now always boots directly against `https://api.signalbridge.in` and never exposes host-entry UI.
- Removed the iOS app's legacy primary-host component and configurable-host boot path, and tightened watchlist/strategy card actions with compact capsule buttons better suited to the mobile layout.
- Refined the Android and iOS dashboard headers with icon-led branding, a cleaner workspace label, and lighter live/menu controls so the top bar feels less flat and more premium.
- Added left-right swipe navigation on the Android and iOS dashboards so users can move between Watch, Trade, Positions, Alerts, and More without relying only on the bottom tab bar.
- Reworked the iOS login form fields into a cleaner stacked auth layout with labeled custom inputs, better spacing, and a more polished card width so the sign-in screen no longer feels visually off.
- Fixed the iOS login text fields to explicitly render entered text and cursor tint on the custom auth inputs so usernames and passwords stay visible against the styled field background.
- Fixed the Android dashboard header safe-area handling so the top bar no longer collides with the phone clock or front camera, and strengthened the shared mobile brand mark styling so the icon reads with more contrast in both apps.
- Added a persistent light/dark theme toggle to the mobile Menu in both the Android and iOS apps, with app-wide appearance updates backed by local preference storage.
- Replaced the mobile dashboard swipe threshold logic with real paged containers on Android and iOS, so left-right swipes now animate interactively and reveal the next screen progressively while dragging.
- Fixed Android dark-theme system bar styling so the phone navigation buttons now follow the selected appearance instead of staying on a mismatched light navigation bar.
- Expanded the mobile appearance controls on Android and iOS from a manual toggle into four modes: follow system theme, automatic time-based switching (light at 6:00 AM and dark at 6:00 PM), manual light, and manual dark.
- Fixed the Android automatic-theme clock state to use lint-safe Compose state updates, resolving the `ProduceStateDoesNotAssignValue` build failure during `lintDebug`.
- Fixed Android dashboard pager state synchronization so tab taps and left-right swipes no longer snap back to `Watch` after page selection.
- Added branded maintenance-mode handling across web, Android, and iOS so backend outages now show a proper SignalBridge unavailable screen with retry instead of raw ELB/backend error behavior.
- Fixed the web maintenance/marketing brand image path to use the shipped SVG logo asset so the icon appears correctly in production builds deployed to Amplify.
- Removed user-facing backend host exposure from Android and iOS outage/error copy so the apps no longer display the raw API URL during connection failures.
- Fixed Android maintenance mode theming so outage screens now follow the system light/dark theme and use higher-contrast text on light backgrounds.

### Notes

- The backend now uses native awaited Motor calls on the main request/live-state paths and across the main async runtime coroutines. Remaining synchronous-style compatibility calls are intentionally limited to synchronous helpers, serializer/snapshot code, and worker-threaded runtime support paths.
- Validation in this environment was limited to `PYTHONPYCACHEPREFIX=/tmp/pycache python3 -m compileall apps/backend-python/app`; `pytest` is not installed here.
